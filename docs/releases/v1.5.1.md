# LAN Messenger 1.5.1

*Everything since 1.3.0 (1.4.0 and 1.5.0 were not published; their work is included here).*

**New in 1.5.1:** choosing network folders in the server setup.
- *Browse* on the *Where to keep the data* page now opens the Windows folder picker, which lists **Network**
  (shares on a NAS or another PC). The old picker only showed this PC's drives.
- A **mapped drive letter** (e.g. `Z:\Messenger`) is recognised: setup offers its real network path
  (`\\NAS01\Messenger`) instead of saying the drive does not exist. (Setup runs as administrator, and Windows
  hides mapped drives from it; the background service can't use drive letters either.)
- In the server console, *Browse* for folders works again when the console runs on the server PC itself
  (the usual case with the background service).

Studio chat, file sharing and screen sharing that runs **entirely on your own network**: nothing goes to the
internet. Install the server once, the client on every PC.

> **Read "Upgrading" below before you update the server.** Two new defaults clean up old data:
> shared files are deleted after **3 days** and messages move out of the app into text logs after
> **90 days**. You can change both before or after upgrading.

## Highlights

### Reminders and scheduled messages
- **Reminders**: *remind me about this message*, about a chat, or about anything
  (*Book the review room for Friday*). Pick *In 20 minutes*, *This evening*, *Tomorrow 09:00* or an exact
  time. A pop-up appears on time with **Open chat**, **Snooze** and **Done**. Reminders live on the
  server, so one that comes due while your PC is off shows up at your next sign-in.
- **Scheduled messages**: write now, send later (clock button next to *Send*). A strip in the chat shows
  what is waiting; edit, send now or cancel it at any time. The server sends it on time even when your PC
  is off.
- The home page shows what's **Coming up**.

### Buzz
- **Buzz** someone who is heads-down: their window shakes, glows and rings, even on *Do not disturb*.
- If their messenger is minimised or in the tray, it pops up as a **phone-style view on the right edge of the
  screen**, above other windows for 15 seconds, with your chat open.
- Once per 20 seconds per person. Each person can switch it off (Settings), and so can the admin (server-wide).

### Compact "mobile" view
- A narrow window docked to the right side of the screen: the chat list or one chat at a time, like a phone.
  Toggle it from the rail or with **Ctrl+Shift+M**. Pin it to stay above your other windows.

### Themes
- Quick **light / dark** switch in your profile menu, plus a **System** theme that follows Windows.
- **Festival themes** on **15 August**, **26 January** and **Christmas** (24–26 Dec): festive colours,
  an animated home-page banner and the festival sticker pack first. Switch them off in Settings.

### Chat history, backups and storage (server)
- **Readable chat backup**: every night the server writes all new messages to plain text files, one per chat
  per month (`backups\Chat logs\2026-09\Room - Comp Team (r12).txt`). Pick another folder, or run it now,
  from the console.
- **Message retention**: messages older than **90 days** move out of the app into those text logs. Nothing
  is deleted before it is in the logs. Set it to 0 to keep everything in the app.
- **Shared files are kept for 3 days** and then deleted from the server; the chat shows how long a file
  is still available. Change it (or set 0 for forever) under *Settings → Chat backup, history and files*.
- The console dashboard shows the last chat backup and a warning if **discovery** is off.
- **Busy ports** are explained: if port 5150/5151 is taken, the console names the program using it.

### Installing
- **Choose where the server keeps its data.** A new setup page asks for four folders: the server data
  (database and settings, on a local disk), shared files, backups and chat logs, and the log. The last three
  can be on another drive or a network share (`\\server\share\...`). The page checks each folder and explains
  what a network share needs when the server runs as the background service. Change them later under
  console → *Settings*, which now also has a **Log folder**.
- **The client installs without administrator rights.** Setup asks *Install for me only* (no admin needed) or
  *for all users*; IT can pass `/CURRENTUSER` or `/ALLUSERS`. The server still needs an administrator once at
  install time: only an administrator can open Windows Firewall for other PCs and register the background
  service.
- **The data folder is locked down**: in service mode only Administrators and the service can open it, because
  it holds every chat. Before, any user signed in on the server PC could copy the database.

### Long text and Nuke scripts
- A Nuke script in chat now shows a **5-line preview** (other long text keeps 12), with *Show all*, *Copy*
  and *Save* as before.
- Paste something long and a hint appears above the message box: *"Nuke script · 422 lines — sends as a compact
  card · **Send as .nk file instead**"*. Enter sends the card; one click sends a `.nk` or `.txt` attachment.
  (Cards stay in the chat as long as messages do; attached files follow the file clean-up period.)

## Security and reliability (from a full code audit)
- **Shared PCs:** signing out now clears everything from the previous account (chats, reminder pop-ups,
  screen sharing), so the next person to sign in sees none of it.
- **Server console:** a remote console now remembers the server's identity (like the client does) and
  never falls back to an unencrypted connection, so the admin password can't cross the network in plain text.
- **Passwords:** changing or resetting a password signs out that person's other PCs. Wrong-password limits
  can no longer be bypassed by trying many at once, and the *change password* screen is limited too.
- **Server protection:** limits on connections, on data waiting for a slow client, on parallel uploads
  (4 per person) and on disk space during uploads; the pipeline API slows down wrong-key guessing.
- **Reminders and scheduled messages:** one broken item can no longer hold up everyone else's. A
  scheduled message that is more than 12 hours late (server was off) is marked failed instead of being sent late.
- **Nightly jobs** (database backup, chat backup, retention, file clean-up) run independently: one failure no
  longer stops the others. A big first chat export no longer pauses chat.
- **Nothing lost:** a message edited after its nightly backup, and final poll results, are written to the chat
  logs before the message moves out of the app. Files that no message points to any more are cleaned up.
- **Settings:** a wrong value in `config.json` no longer stops people from signing in (and a typo can't switch
  encryption off); a damaged client settings file no longer stops the app from starting.
- **One window error can't take the server down.** The server console, remote console and client now log an
  unexpected error (`server.log`, `%APPDATA%\LANMessenger\console.log`, `%LOCALAPPDATA%\LANMessenger\client.log`),
  show a short message and keep running. Every console page is now tested with the server running, stopped and
  as a service.
- **Start-up problems are explained, not fatal:** a files folder or share that is unavailable no longer stops
  the server (chat works, the dashboard shows the problem); a failed start frees the port so *Start* really
  retries; an empty (damaged) database file is no longer silently replaced by a new one; clear messages for a
  database in use by another program, a damaged certificate and invalid ports. Setup waits for the service to
  run before it opens the console.
- **Wrong system clock:** backups are pruned by file age and never delete the copy just made; retention skips
  one night after a big clock jump.
- **Odd requests** (found by fuzzing every server command with bad input) get a clean "invalid request"
  instead of a server error or a dropped connection.
- **Trusting a replaced server** now reconnects straight away (before, you had to click *Sign in* again).

## Performance fixes
- A busy chat left open all day kept every message on screen. Memory now stays flat: the newest 150 messages
  are shown and scrolling up shows older ones. In our soak test (1,800 messages into one open chat) the
  client went from 437 MB to about 155 MB.
- File transfers update the screen 10 times a second instead of thousands.
- Image previews are decoded at preview size and cached.
- The festival banner stops animating when it is out of sight.
- Messages sent while a PC was disconnected now always appear after it reconnects.
- A reminder can no longer pop up twice, and a buzz no longer reopens a window you had hidden in the tray.
- Temporary zips of sent folders are cleaned up; deleted messages no longer count as unread.

## Install

1. **Server:** run `LANMessenger-Server-Setup-1.5.1.exe` as administrator on an always-on PC. Keep the
   tasks *Allow through Windows Firewall* and *Run as a background service*, and pick the data folders
   (the defaults are fine).
2. Open **LAN Messenger Server** from the Start menu and sign in as **admin / admin**; you must choose a new
   password straight away. Add people under **Users** (or *Import CSV*) and set up **Designations**.
3. **Clients:** run `LANMessenger-Client-Setup-1.5.1.exe` on every PC. Leave the server address empty and
   the client finds the server by itself (enter its IP only if the PC is on another subnet).
   Choose *Install for me only* if you don't have administrator rights. Silent install for IT:
   `LANMessenger-Client-Setup-1.5.1.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /ALLUSERS /SERVER=192.168.1.10`

## Upgrading from 1.3 (or a 1.4.0 test build)
- **Upgrade the server first**, then the clients. Run the new setup over the old one; accounts, messages,
  files and settings are kept and the database updates itself on start.
- In the console use **Settings → Back up now** before upgrading.
- Upgrading keeps your data folders where they are and skips the new *Where to keep the data* page; move them in
  console → *Settings* if you want to. (1.4.0 was never released; its test builds upgrade like 1.3.)
- **Check the new defaults before or right after upgrading** (*Settings → Chat backup, history and files*):
  - **Files are deleted after 3 days.** On the first hourly clean-up after the upgrade, shared files older
    than 3 days are removed from the server. Set a larger number (or 0 = keep forever) if you need them.
  - **Messages older than 90 days move to the text logs** at the next nightly run (the backup hour, 2 AM by
    default). They stay readable in `backups\Chat logs`, but are no longer in the app. Set 0 to keep them.
- The **remote server console** asks you to confirm once if the server's identity is new to it, and
  now only connects to servers with encryption (TLS) on, which is the default.
- To update every PC from the server, copy `LANMessenger-Client-Setup-1.5.1.exe` into the server's
  `updates` folder (console → *Client updates*); clients offer to install it.
- 1.3 clients keep working with the new server, but can't buzz, set reminders or schedule messages. Update
  them soon.

## Requirements
- Windows 10 or 11, 64-bit, on every PC
- Network ports on the server: **TCP 5150** (chat, files, screen sharing), **UDP 5151** (discovery),
  **TCP 5152** only if the pipeline API is switched on. The server setup allows the server program through
  Windows Firewall, which covers all three.

## Known limits
- One server per studio; load-tested with 500 people online at once: 500 signed in within 2 s, ~390,000 deliveries with none lost, typical delivery 3–40 ms, server ~460 MB of RAM. The server's chat work runs on one CPU core: around 500 *very* busy
  users it gets slower (up to about a second in a 500-person room flooded with posts), it doesn't lose messages.
- The installers are not code-signed: Windows SmartScreen may say "Windows protected your PC" the first
  time (*More info → Run anyway*).
- Screen sharing is view-only (no remote control).
- The pipeline API uses plain HTTP; keep its key private and switch it off if you don't use it.
